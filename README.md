# 牛马团队 (NiuMa Team)

> 一群不知疲倦的 AI「牛马」，把你的需求变成可合并的代码 —— 你只管当甲方，脏活累活有人接。

## 这是什么

牛马团队是一套**全自动软件开发流水线**。在这里，你是甩手掌柜，AI 是打工牛马：

1. 你把需求写成任务单，往队列里一扔；
2. 包工头自动派活，搬砖牛马认领开工；
3. 代码写完自测一遍，交给挑刺判官验收；
4. 验收通过，交付合并；不通过？打回重做，没有怨言。

你唯一的工作是**把需求说清楚**——毕竟连 AI 都治不好需求模糊这个病。

```
任务单（打上标记）
   │
   ▼
包工头 ──▶ 搬砖牛马 ──▶ 挑刺判官 ──▶ ✔ 交付合并
 派活管人     隔离搬砖       铁面验收
```

## 为什么叫「牛马」

「牛马」是打工人的自嘲，形容埋头苦干、任劳任怨。这个项目的目标正是打造一支这样的 AI 团队：

- **干活不抱怨** —— 任务单写清楚就开工，不参加需求评审，不写周报，不发朋友圈吐槽；
- **随叫随到** —— 包工头定时巡逻，新任务进来立刻有人认领，没有「在忙」这种借口；
- **干完还自查** —— 写代码的和审代码的是两拨人，互相把关，想摸鱼混过去？门都没有；
- **成本可控** —— 并发上限、模型选择、重试策略全部可配置，牛马再多也不烧穿预算。

## 团队分工

| 角色 | 花名 | 职责 |
|------|------|------|
| 调度器 | **包工头** | 自己不写一行代码，专职派活：巡查任务队列、分配工作、盯进度；有牛马掉线了负责拉起来接着干——工地上出任何事都是他的事 |
| 开发 Agent | **搬砖牛马** | 一线苦力。在与其他任务完全隔离的独立工位上按测试驱动的流程搬砖：实现需求、编写测试、提交变更，交活之前自己先过一遍 |
| 审查 Agent | **挑刺判官** | 铁面质检员。以第三方视角对交付的代码逐条挑刺、跑端到端验证；眼里揉不得沙子，不合格一律打回返工，没有「下次注意」这回事 |

## 任务的一生

每个任务从出生到退休都有清晰的状态轨迹，全程可追溯——比很多公司的流程规范多了：

```
待认领 ──▶ 开发中 ──▶ 待审查 ──▶ 审查中 ──▶ ✔ 光荣退休（已交付）
              ▲                     │
              └───────── 返工中 ◀────┘ （被挑出毛病，带着反馈回去重做）
```

- **入职即上岗**：任务单打上标记就进入待认领池，等包工头分配；
- **带薪改错**：审查不通过会被打回返工，但反馈会原样带到，不会白改；
- **不许猝死**：任何牛马中途崩溃或超时，包工头都能发现并恢复现场，任务绝不烂尾；
- **保留人工关卡**：重要任务可以声明「审过也先别合」，最终拍板权还在你手上——关键决策，甲方亲自来。

## 我们的厂规

- **先测后码**：没有设计画布和测试计划就不许动手。返工是天下最惨的牛马，能一次干对就别折腾第二遍。
- **不自审自夸**：自己写的代码自己说好不算数。开发和审查是两个独立会话，互相制衡，谁也别想糊弄谁。
- **好钢用在刀刃上**：硬骨头交给强模型啃，例行检查让轻量模型跑腿。质量要保住，钱包也要保住。
- **不绑死任何一家**：不锁定编码 Agent，不锁定代码托管平台，统一抽象层接入主流工具——牛马可以换，工地不能停。
- **默认关起门干活**：AI 会把任务内容当圣旨执行，所以流水线天生面向私有仓库与可信环境设计；要开门营业，就得收紧权限、留好人工关卡。
